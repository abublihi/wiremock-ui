# Milestone 2A — QA Basics Backend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every M2 backend capability the QA UI (Plan 2B) needs: user accounts with roles and sessions, ownership rules on mocks, integrations and an endpoint catalog, building mocks from the catalog, bundle import and baseline seeding, the request log with near-miss explanations, and an audit log.

**Architecture:** Same shape as M1. Logic lives in plain modules under `src/server/` that take dependencies as arguments; HTTP handlers in `src/server/http/` stay framework-free and are wrapped by one `withAuth` wrapper that authenticates and checks a permission before the handler runs; TanStack Start route files under `src/routes/api/` stay one-line adapters. All new Redis state shares one ioredis connection created by `createStores(config)`.

**Tech Stack:** As M1, plus `bcryptjs` (pure JS bcrypt, no native build on alpine/arm64) and `jsonpath-plus` (JSONPath evaluation for near-miss explanations).

**Spec:** `docs/spec.md` — read "Core concepts", "Users, roles and ownership", "Import, export and baseline seeding", "Scenarios, recording, request log and webhooks" (request log part only), "Security" §3, and **Amendments** (A1–A6). Follow-ups from M1: `docs/m1-followups.md`.

## Global Constraints

- Roles exactly `viewer`, `tester`, `developer`, `admin`, with the permission matrix in spec "Users, roles and ownership"; `baseline` mocks are read-only for everyone except admins and the import path.
- Passwords hashed with bcrypt cost 12 (tests may inject a lower cost). Sessions live in the store, 12-hour lifetime (43200 s). Session cookie `wmui_session`, `HttpOnly`, `SameSite=Lax`, `Path=/`, `Secure` when the request is HTTPS (or `X-Forwarded-Proto: https` with `TRUST_PROXY=true`, or `PUBLIC_UI_URL` starts with `https://`). Cookie value is `<sessionId>.<base64url HMAC-SHA256(sessionId, SESSION_SECRET)>`.
- CSRF: cookie-authenticated `POST`/`PUT`/`PATCH`/`DELETE` require header `X-CSRF-Token` equal to the session's token, else `403` `{ error: 'CSRF token missing or invalid' }`. Basic-auth requests (scripts) need no CSRF token. No response ever carries `WWW-Authenticate` (Amendment A4).
- Login rate limit: 10 failed-or-not attempts per 15 minutes (900 s) per client IP, on both `POST /api/session` and Basic auth; the 11th gets `429` `{ error: 'Too many login attempts; try again later' }`.
- First admin from `ADMIN_USER` / `ADMIN_PASSWORD` is created only when no user exists; an existing user is never overwritten.
- Writes still require `Content-Type: application/json` (`415` otherwise).
- Priorities: key-matched catalog mocks priority `5`, default mocks priority `10`.
- Audit entries kept 30 days (2592000 s); `actor` is the username, or `system` for sync/seed.
- Redis keys (new): `user:{id}`, `users:all`, `users:by-name:{username}`, `session:{id}`, `ratelimit:login:{ip}`, `integration:{key}`, `integrations:all`, `catalog:{integration}:{endpoint}`, `catalog:{integration}` (set of endpoint keys), `audit:log` (sorted set, score = epoch ms).
- New env vars: `TRUST_PROXY` (default `false`), `PUBLIC_UI_URL` (optional), `SEED_PATH` (optional), `SEED_PRUNE` (default `false`).
- Every mock that enters the store has `metadata.wiremockUi.version` ≥ 1 (fixes the M1 follow-up "unversioned stub can never be updated").

## Review Focus

1. **A tester edits or deletes a colleague's mock, or a baseline mock, through the API** — `403`, nothing changes in WireMock or the store. → Task 3, `tester cannot touch others' or baseline mocks`.
2. **Someone guesses passwords** — the 11th attempt from one IP within 15 minutes gets `429` even with the right password; Basic auth counts too. → Task 2, `rate limit`.
3. **The service restarts with `SEED_PATH` set while a tester owns a mock whose id is also in the bundle** — the tester's mock is untouched and the seed report lists it as skipped. → Task 7, `never touches person-owned mocks`.
4. **A plain WireMock mapping (no `wiremockUi` metadata) is imported and later edited in the UI** — the edit succeeds (no `409`). → Task 7, `imported plain stub is editable`.
5. **A mock built from the catalog actually matches the request a client sends** — the built stub, pushed to real WireMock, answers the example request with the chosen status, and a request with another key value falls through to the default mock. → Task 6, `built mocks match real requests`.
6. **The last admin demotes, disables or deletes themselves** — refused with `409` `{ error: 'At least one active admin is required' }`. → Task 3, `last admin`.
