# Milestone 2B — QA Basics UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The browser UI for Milestone 2 on top of the merged 2A API: sign-in, the mock list, a catalog-first Simple mock editor with an Advanced JSON mode, the live request log with near-miss explanations, catalog management, and admin pages (users, audit, import) — in English and Arabic with RTL.

**Architecture:** TanStack Start file routes under `src/routes/` (pages) next to the existing `src/routes/api/*`. Pages fetch through one typed client in `src/ui/api/` with TanStack Query; no page calls `fetch` directly. UI components come from shadcn/ui (radix base) on Tailwind v4 with the project's own tokens. Strings live in `src/ui/i18n/{en,ar}.ts`; the locale is a cookie so the server renders the right `lang`/`dir`. Pure UI logic (presets, editor sync, diff rendering) lives in plain `.ts` modules with unit tests; components get React Testing Library tests; three Playwright flows run against the real stack.

**Tech Stack:** Tailwind CSS v4, shadcn/ui (radix), `lucide-react`, `@tanstack/react-query`, CodeMirror 6 (`@uiw/react-codemirror` + `@codemirror/lang-json`), `@fontsource/ibm-plex-sans`, `@fontsource/ibm-plex-sans-arabic`, `@fontsource/ibm-plex-sans-condensed`, `@fontsource/ibm-plex-mono` (self-hosted: the tool runs on closed networks), `@testing-library/react` + `happy-dom` + `msw` for component tests, `@playwright/test` (chromium only) for e2e.

**Spec:** `docs/spec.md` — read "Users and UX principles", "Core concepts", "Mock editor: request matching" and "Mock editor: responses" (Simple-mode columns only), "Request log (live)", "Users, roles and ownership", Amendments A4–A6. API reference: `README.md` sections "Authentication", "Importing a bundle", "Catalog notes"; server routes under `src/routes/api/`.

## Global Constraints

- **Design tokens** (define once as CSS variables in `src/ui/styles.css` under `@theme`; components use semantic classes only, never raw hex):

| Token | Light | Dark | Use |
|---|---|---|---|
| `--canvas` | `#F3F5F8` | `#0F141B` | page background |
| `--surface` | `#FFFFFF` | `#161D27` | cards, tables, drawers |
| `--ink` | `#17202E` | `#E6EAF0` | text |
| `--muted-ink` | `#5B6676` | `#9AA5B4` | secondary text |
| `--signal` | `#0B7A75` | `#3FB8AF` | primary actions, links, focus ring |
| `--hazard` | `#F0A202` | `#F0A202` | test-environment strip, "no match" stamp |
| `--mismatch` | `#C8402B` | `#E46A55` | failed field rows, destructive |
| `--match` | `#2E8B57` | `#4CC38A` | matched rows/fields |

  Map shadcn's variables (`--background`, `--foreground`, `--primary`, `--destructive`, `--ring`, …) onto these. Dark mode follows `prefers-color-scheme` plus a user toggle stored in cookie `wmui_theme` (`light` | `dark` | `system`).
> **Scope change (user, during execution):** Arabic and RTL are not required (spec Amendment A7). The UI is English only; strings still go through `t()` with keys in `en.ts`. Ignore every Arabic/RTL/locale requirement below; logical Tailwind classes are fine but no longer enforced.

- **Type:** body/UI `IBM Plex Sans`; page titles `IBM Plex Sans Condensed` 600; URLs, ids, JSON, header names `IBM Plex Mono`. Scale: 12 / 14 (base) / 16 / 20 / 28 px.
- **Signature element:** a 6 px hazard strip (45° amber/ink hatching) across the top of every page with the label "Test environment — mocks only, never real data" (`role="note"`), and in the request log a hatched amber **No match** stamp on unmatched rows that opens the near-miss explanation. Nothing else uses the hatch.
- **Layout:** a side rail (start side; flips in RTL) with Mocks, Request log, Catalog, and — by permission — Users, Audit, Import; top bar with user menu (change password, sign out), language and theme toggles. Responsive to 360 px: the rail becomes a sheet.
- **Copy:** sentence case, active verbs that name the outcome ("Save mock", "Delete mock", toast "Mock saved"), errors say what happened and how to fix it, empty states invite the next action. Every user-visible string goes through `t()`; `ar.ts` has every key of `en.ts` (enforced by a test).
- **Locale:** cookie `wmui_lang` (`en` | `ar`, default `en`); `<html lang dir>` set on the server render; use logical Tailwind classes (`ms-`, `me-`, `ps-`, `pe-`, `start-`, `end-`, `text-start`) only — no `ml-`/`mr-`/`left-`/`right-`/`text-left` (enforced by a test that greps `src/ui` and `src/routes`, excluding `api/`). URLs, JSON and ids stay LTR (`dir="ltr"` on mono elements).
- **API client:** every write sends `Content-Type: application/json` and `X-CSRF-Token` (token from `GET /api/session`, kept in memory, refetched after reload); errors are `{ error }` → thrown `ApiError { status, message }`; 401 anywhere → redirect to `/login?next=…`; 409 on mock save → "Someone changed this mock since you opened it. Reload to see their version." with a Reload action.
- **Permissions in the UI** use `can()` / `canEditMock()` from `src/server/auth/permissions.ts` (type-only imports; safe on the client). Controls the user cannot use are hidden (nav) or disabled with a tooltip saying why (row actions on someone else's or a baseline mock).
- **Simple-mode status presets** (exact): Success → 200, Not found → 404, Validation error → 400, Server error → 500, Timeout → status 504 with delay 30 s. "Slow response" switch → `delayMs` (seconds input, 1–120). "Break the connection" select → the four `fault` values with plain labels: Empty response, Garbled chunk, Random data then close, Connection reset.
- **Request log polling:** every 2000 ms while the tab is visible (`document.visibilityState`), paused when hidden, using `since` of the newest row for incremental fetches; manual "Pause live" toggle.
- **Accessibility floor:** visible focus ring (`--signal`), every icon-only button has an `aria-label`, dialogs have titles, tables have header cells, `prefers-reduced-motion` disables the live-row flash.

## Review Focus

1. **A tester opens a baseline or a colleague's mock** — it opens read-only with a "Duplicate to my mocks" action; no Save/Delete is offered. → Task 4 `read-only for mocks the user cannot edit`.
2. **Two people edit the same mock** — the second save shows the 409 message with Reload, and nothing the user typed is lost until they choose to reload. → Task 5 `conflict keeps the draft`.
3. **The Advanced JSON is edited into something Simple mode cannot represent** — Simple mode becomes read-only with "This mock uses options Simple mode can't show. Edit it in Advanced." instead of silently dropping fields. → Task 5 `simple mode refuses lossy round-trip`.
4. **Keyboard and screen-reader users** — every page has no serious axe-core violations, dialogs trap and return focus, and every icon-only control is labelled. → Task 9 e2e (`a11y.spec.ts`).
5. **The request log tab is left open in the background for hours** — no polling while hidden; resumes with an incremental `since` fetch. → Task 6 `pauses when hidden`.
6. **Session expires mid-task** — the next API call redirects to sign-in with `next` set and the user lands back where they were. → Task 2 `401 redirects with next`.
